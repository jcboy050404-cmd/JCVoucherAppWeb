## Goal
Make the app responsive across phones (portrait & landscape) and tablets (portrait & landscape). Today the app is locked to portrait and every screen is a single full-width column that stretches awkwardly on wide screens.

## Approach
Create one small shared helper for responsive sizing, then update `main.dart` + each screen. Strategy: allow all orientations, switch grids to width-aware column counts, and constrain list/modal content to a max width on tablets (centered with gutters) so nothing stretches ugly-wide.

## Step 1 — New shared helper: `lib/responsive.dart`
A tiny utility (no dependencies):
- `Responsive(BuildContext context)` exposing:
  - `width`, `height`
  - `isPhone` → shortest side < 600
  - `isTablet` → shortest side ≥ 600
  - `contentMaxWidth` → 720 (max column width for lists/modals)
  - `gridColumns({double itemWidth = 360})` → `(width / itemWidth).ceil().clamp(1, 4)` — drives stat/quick-action/voucher grids by available width instead of a hardcoded 2.
- `Widget constrainedContent({Widget child})` → `Center(child: ConstrainedBox(maxWidth: 720, child))` reused to clamp lists/forms on tablets.
This keeps every screen's changes to one or two lines of layout logic.

## Step 2 — `lib/main.dart`
- Change `SystemChrome.setPreferredOrientations` to allow all four orientations (remove the portrait-only list) so tablets can be used in landscape.

## Step 3 — `lib/screens/dashboard_screen.dart`
- Replace the two `GridView.count(crossAxisCount: 2)` inside Income & Sales and Voucher Overview sections with `GridView.builder`/`SliverGrid` using `Responsive.gridColumns()` — e.g. 2 columns on phone, 3–4 on tablet.
- Wrap the dashboard body sections in `constrainedContent` so the section cards don't span the full tablet width (centered column).
- The Quick Actions already use a manual 2x3 `Row` of `Expanded` cards — convert to a `Wrap` or width-based grid so tablets show 3 per row. Card `height: 110` stays (it's a card, not a width problem).

## Step 4 — List screens (constrain width + optional grid)
Apply `constrainedContent` around each list so cards don't stretch. Files:
- `lib/screens/voucher_list_screen.dart` — wrap the `ListView.builder` body; optionally show 2 columns of voucher cards when width ≥ 720 (use `Responsive.gridColumns(itemWidth: 420)`).
- `lib/screens/active_vouchers_screen.dart` — same: constrain the search box + list; 2-col grid of session cards on tablet.
- `lib/screens/profile_list_screen.dart` — constrain the `ListView.builder`; 2-col on tablet.
- `lib/screens/script_list_screen.dart` — constrain the `ListView.builder` of `ExpansionTile`s.
- `lib/screens/scripts_screen.dart` — constrain the `ListView.builder`.

For the grid-on-tablet approach I'll keep it simple: if `isTablet`, render a `SliverGrid`/`GridView` with the computed column count; otherwise the existing single-column `ListView`. Item cards themselves already use flexible inner `Row`s/`Expanded`, so they adapt to the narrower grid cell.

## Step 5 — Form screens (constrain width)
- `lib/screens/generate_screen.dart` — the `CustomScrollView` body's form sections currently span full width. Wrap the `Form` content in `constrainedContent` (max 720) so on a tablet the form reads as a centered column instead of stretching. No structural changes to the fields.
- `lib/screens/login_screen.dart` — the `SingleChildScrollView` content (logo, saved-router list) wrap in `constrainedContent`. The modal add/edit router sheet (`showModalBottomSheet`) gets a `Constraints`/maxWidth via `showModalBottomSheet`'s `constraints` param so it doesn't span the whole tablet width.

## Step 6 — Bottom-sheet modals on tablets
For the larger modals (`_showPrintOptionsModal`, `_showPrintPreviewModal` in dashboard & voucher_list; script add/edit; voucher print preview), pass `constraints: BoxConstraints(maxWidth: 720)` to `showModalBottomSheet` and center via `Align` so on tablets the sheet is a centered panel rather than edge-to-edge.

## Non-goals (intentionally)
- No font-size scaling / sp-based typography (low value, big churn; existing `FittedBox` on stat values already handles overflow).
- No master-detail rewrite for tablets — width constraint + grids gives a clean responsive feel at far lower risk.
- No changes to models, services, or business logic. Print/PDF logic untouched.

## Verification
- `flutter analyze lib/` — must show no new errors/warnings (existing `withOpacity` deprecation infos are pre-existing and out of scope).
- Manual reasoning checks for each screen at three widths: ~360dp (small phone portrait), ~800dp (tablet portrait / large phone landscape), ~1200dp (tablet landscape) — confirm content is centered/constrained and grids add columns rather than stretching.
